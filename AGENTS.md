# Working on this design bible

Read `README.md` and the current review record before making changes.

- Treat `reference/` as a read-only source archive. Do not alter the original bible.
- Use `tokens/design-tokens.json` as the token source. Use `src/products.json` for the product chapters. Rebuild after edits; never patch only the generated artifact.
- Preserve established brand assets. New marks and product positioning remain explicitly proposed unless the owner decides otherwise.
- FireFlow is one product with three core parts: the FireFlow orchestration engine, MemoryTree (persistent memory), and FlameChorus (chat UX engine). Keep MemoryTree and FlameChorus subordinate within FireFlow, with no peer product chapters or product placeholders. Spell FlameChorus as one word.
- Galactica is the fifth product identity and is live. Its AI/blockchain privacy positioning follows the owner’s brief. Use the owner-directed Galactica.com wordmark with .com and a bold orange dot. The checked-in outlined lockup is a family adaptation; the disclosure diagram is explanatory artwork. Keep proposed tokens separate from measured source claims.
- No invented product capabilities, availability, metrics, privacy guarantees or approvals.
- Keep fixed light/dark specimens locally scoped. Test labels, states, controls and actual rendered examples, not only token swatches.
- For a requested review loop, use separate strategy, visual and accessibility reviewers. Collect findings, let an integrator make corrections, then verify closure in another round. Reviewers are read-only. Use the versioned workflow prompts/schema and record evidence hashes.
- Run the build and the checks appropriate to each change. Review screenshots after visual changes; do not claim visual QA based only on a source inspection.
- Do not create external messages, publish, deploy, commit or push unless the user asks for that next step. The intended GitHub destination is private.
